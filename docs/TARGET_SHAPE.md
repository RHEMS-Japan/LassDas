# LassDas の最終形 (確定 2026-08-21)

発注者と合意した確定版。維持/廃止評価 + 独立 2 系統クロスチェック (issue #9) と、実行層の議論 (2026-08-21) の帰結。以後の全ての実装・修理はこの絵に向かう。

## 一枚の絵

```
Backlog チケット
   │  (受付: 起票者・カテゴリの拒否既定 — LassDas 中核)
   ▼
Hermes カンバン ──────────── 進行はすべて Hermes 純正
   │  カード生成 / 配車 / レビュー列 / 差し戻し / 盤面 UI (Hermes One)
   ▼
Hermes 純正エージェント ───── 実行も Hermes 純正 (ハーネス 1 本)
   │  実装役もレビュー役も Hermes エージェント。
   │  モデルはゲートウェイ経由で別会社 2 系統を指定 (ベンダー多様性はモデルで担保)
   ▼
LassDas 中核 = 関所 ───────── ここだけが自前 Go として残る
   │  ・質問は 2 回まで (記録と連鎖)
   │  ・2 者レビューの検算 (成果物 digest 束縛・1 人でも差し戻しなら不成立)
   │  ・納品ゲート (レビュー+検証が揃わない PR は物理的に出せない)
   │  ・Backlog への受付/質問/報告の投稿
   ▼
GitHub PR (納品)
```

## 設計原則

**一番シンプルな形から始め、実測が「不足」を示した箇所だけ分離する。** 複雑さを前払いしない。

- **分離条件 (事前確定)**: 実装品質が原因の受入失敗が連続 2 回 (= レビュー指摘を実装役が解消し切れずに終わる) になったら、実装役だけを claude CLI の外部呼び出しに分離する。それ以外の理由 (受付・進行・関所の不具合) では実行層を触らない。
- **審判の土台相関は受け入れる (記録)**: レビュー 2 者が同一ハーネスに乗る相関リスクは、①別会社モデル 2 系統 ②観点の意図的分離 (差分先読み / 実際に動かす — Hermes 純正手順書の規定) ③レビューとは別の決定論的検証 (テスト・lint) ④関所の検算、の 4 層で補い、残余は受容する。実測 5 回の失敗は全て「審判の見落とし」ではなく「審判が見つけ続けて収束しない」型だった。

## 残すもの / 捨てるもの

**残す (中核 = policy kernel)**: `internal/worker` の検査・拒否権・digest 束縛 / `internal/hook` の質問プロトコルと報告 / `internal/backlog` + attendant の Backlog 橋 / controller の納品直前再検証。いずれもテストの厚い層 (77〜90%)。

**捨てる**: 自前の進行配線 `internal/runner` (テスト 0%・実失敗 3 件の発生地) と付随の二重実装 / **claude・codex CLI の同梱と版追従** (分離条件が発動しない限り) / 旧 GitHub Actions 構成一式 / 未使用の DynamoDB/Lambda 経路。

**外に出さない前提**: Hermes 側は「レビューを素通りして完了できる」等の穴を持つが、納品は中核の関所を通らない限り成立しないため、進行・実行側の緩さは納品物の品質保証を破れない (台帳外カードが 1 行で死ぬ現在の性質と同じ原理)。

## この絵で解消される既知問題

- 収束しない差し戻しループ (608) → Hermes 純正の巡別レンズ + 過去試行の受け渡しが進行・実行に備わる
- レビュー容量の天井 (610) → レビュー役がリポジトリを直接読むため、詰め込み上限自体が消える
- 進行配線の無検査 (テスト 0 の 1,272 行) → 配線ごと消える
- CLI の版・フラグ地雷 (v2.1.205 スキーマ無視 / --bare 衝突 / --ignore-user-config のゲートウェイ破壊) → 同梱をやめるため消える
- 保守量 → 自前 Go は 32,186 行 (実測) から**約 27,200 行へ縮小** (削減 5,000 行 = 進行配線 + 旧 GitHub Actions レール + 旧レール専用ストア。全パッケージの処遇表と測定コマンドは docs/M2_MIGRATION.md)。実行方式の分岐ゼロ。さらなる減量 (状態系の残余整理・製品ツールの別リポジトリ化) は M2 完了条件にせず後続整理とする。※v1 の「約 1 万数千行」・v2 の「約 23,000〜24,000 行」はいずれも誤り — M2 設計の独立評価 2 巡で実測訂正 (2026-08-21)
