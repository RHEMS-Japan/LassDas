# 依頼の出し方と、その後 — 課題管理の使い方

対象読者: 依頼を出す人。**何を書くか**は [TICKET_AUTHORING.md](TICKET_AUTHORING.md) にある。ここは**出したあと何が起きるか**と、そのとき何をすればよいか。

## 1. 拾われる条件 (3 つ全部いる)

1. **起票者が、導入のときに決めた 1 人であること。**他の人が立てた課題は、どれだけ正しく書かれていても拾われない。黙って無視される
2. **受付カテゴリが付いていること。**これが自動処理の入口で、付いていない課題は「本体に見せないメモ」として扱われる
3. **「課題の追加」であること。**本体は課題管理の活動を順に読んでいる。読むのは追加の活動だけで、後からの更新は読まない

3 の結果として、**カテゴリは課題を立てるときに付ける**。後から付けるのは、本体がその課題を読む前に間に合えば効くが、読み終わった後なら二度と拾われない。時間任せになるので、確実にしたいなら立て直す。

カテゴリと状態の名前は導入のときに決めている。分からなければ `.lassdas/setup.json` を見るか、導入した人に聞く。

## 2. 出したあと — 状態は本体が動かす

課題の状態は 4 つを行き来する。名前は導入のときに決めたもので、既定ではこうなっている。

| 見えるもの | 意味 |
|---|---|
| 自動処理中 | 動いている |
| 回答待ち | あなたの答えを待っている |
| 処理済み | 納品した |
| 未対応 | 届かずに終わった。コメントに理由がある |

**状態は結果の表示であって、入力ではない。**人が手で状態を動かしても、本体の動きは変わらない。止めたい・やり直したいときに状態を戻しても何も起きない。伝える手段はコメントだけ。

## 3. 質問が来たら

**聞かれるのは、着手する前の一度だけ。** 本体は課題を読み、自分で決められないことを 1 つのコメントにまとめて聞く。そこを通過したあとは、実装でつまずいても、レビューが噛み合わなくても、工程が失敗しても、**あなたには何も聞かない。** 決めなければ進めないことは本体が決め、決めたことは【実装方針】のコメントと最終コメントに「前提」として並ぶ。異論があればそこで分かる。

分からないことがあると、本体は課題にコメントで質問する。選択肢が付いている。

- **書式は自由。**ふつうの日本語で答えてよい。選択肢の記号でも、文章でもよい。読むのはモデルで、決まった書き方を探しているわけではない
- **全部答えなくてよい。**分かるところだけ答えれば進む。足りなければまた聞かれる
- **答えられるのは起票者本人だけ。**他の人が代わりにコメントしても読まれない
- **質問より後に書いたコメントだけが読まれる。**質問より前に書いてあったことは、答えとしては扱われない
- **やめたくなったら「この依頼は取り消します」と書く。**取り消しは他の回答より優先され、対象の repo には何も変更されずに終わる

- **質問を出すかどうかは受付が決める。**設定に判定モデル (`models.reception_judge`) を足しても、**いまの版では受付はそれを一度も呼ばない。**書いても何も起きず、記録にも何も増えない。効き始めるのは次の変更から ([SETUP.md](SETUP.md))

### 着手したあとに人を待つ 2 つの場合

**既定ではどちらも起きない。**導入のときに運用担当者がそう選んだ納品先でだけ起きる。**人が張り付かない使い方をするなら、どちらも既定のままにする。**

| 起きること | 設定 | 既定 |
|---|---|---|
| **本番へ出す前に「Go」を待つ。**staging の確認まで終わったところで止まり、あなたが課題に「Go」とコメントするまで本番へ進まない。待つのは最長 7 日で、過ぎたら本番未反映のまま報告して終わる | `chain.deliver.go_gate` | `off`（待たない） |
| **同じ工程を決められた回数だけやり直したら、そこで終える。**一時的な障害でも、その回数に当たれば「本番環境への反映は完了していません」で終わる | `chain.retry_max_attempts` | `0`（回数の上限なし） |

前者を入れると、夜に出した依頼は朝まで人を待つ。後者を入れると、待てば直る障害が終わりになる。どちらも「人がすぐ見られる」納品先のための設定である。

### 答えないとどうなるか

- 質問が出た日から数えて **1・3・5 営業日目の 10:00 (日本時間)** に、同じ質問が再通知される
- **5 営業日目の 17:00 (日本時間)** が期限。土日は数えないが、祝日は数える
- 期限を過ぎると打ち切られ、**その課題での自動処理は終わる**。あとから答えても再開しない。**答えを本文に書いた新しい課題として出し直す**

## 4. 終わり方の見分け

終わり方は 19 種類あり、**あなたのところに何かが届くのはそのうち 2 つだけ**。

- **変更が PR になった** — 依頼どおりに直せた場合
- **調べた結果が報告された** — 調査だけを頼んだ場合

残りの 17 種類は、**対象の repo にも本番にも一切変更を加えずに止まる**。どれで終わっても課題にコメントが付き、何が起きて何が起きなかったかが書かれる。状態は「処理済み」か「未対応」になる。

**PR は自動でマージされない。**読んでマージするのは人。

### 「内部エラー」で終わるとき

最終コメントに「内部エラーが発生し、依頼を完了できませんでした」「次に行動する人: 運用担当者」「自動再試行: なし」と出ることがある。**これは本体の側では直せない、名前の付いた 3 つの場合だけ**で、それ以外の失敗は本体が手を変えて続ける。

| 起きたこと | 運用担当者がすること |
|---|---|
| 設計から始めるべき依頼だと判定されたが、この実行環境に設計の工程が用意されていない | 設計の工程 (`chain.profiles` の `investigate` / `design_review_a` / `design_review_b` / `design_decide` / `applier`) を設定して、同じ内容で出し直してもらう |
| 同じく設計から始める依頼で、納品先に設計を写し取る役 (`agents.applier`) が無い | 納品先の設定に `agents.applier` を足して、出し直してもらう |
| 受付の判断を記録したファイルが 2 回続けて読めない | 1 回目は本体が自分で受付をやり直すので何もしなくてよい。2 回続けて読めないのは保存先か受付そのものの故障なので、実行環境を見る |

依頼を出した側は、いずれの場合も**出し直す以外にすることはない**。対象の repo にも本番にも変更は入っていない。

**repo の外に何か作られることがある。**依頼を果たすのにデータベースやキューが要ると本体が判断し、導入のときにそれを許していれば、本体はそれを作って使う。作ったものは PR の説明と課題の最終コメントに、種類・識別子・どの工程で作ったか・いつ、の 4 点で並ぶ。**自動では消えない**ので、要らなくなったら消すのは人。許していない種類のものを本体が作ったと申告した場合は、**成果としては報告されず**「許可されていない種類として退けた宣言」として別に出る。本体は作ることを止められるわけではなく、許可されたものとして記録するのを拒んで、退けたと報告するだけ。

**反映のしかたごと作られることがある。**その納品先に「変更を本番まで届ける経路」がまだ無い場合、本体はその経路を作ることを依頼の一部として扱い、作れる部分を**同じ PR に入れて**出す。経路のうち `.github/workflows/` の下のファイルは、導入のときに**中身の決まりを渡したときだけ**、そこで挙げた名前に限って本体が書く。書かれた workflow は PR に載る前に決まりと突き合わされ、外れていれば本体が自分で差し戻して書き直させる。**決まりを渡していなければ本体は 1 つも書かず**、足りない設定が最終コメントに**名前で**並ぶ (「設定してください」という依頼文は付かない)。

**本体は設定を書き換えない。**deploy の workflow を書いた実行でも同じ。足りない設定は、書き足されるのではなく最終コメントに**名前で**並ぶ。

## 5. 止めたいとき

- **質問を待っている間**なら、「この依頼は取り消します」とコメントすれば止まる
- **それ以外のとき**に、課題の側から止める手段は無い。状態を変えても止まらない。本体そのものを止めるしかない (導入した人に頼む)

## 6. 進み具合を見る

盤面 (board) で、いまどの依頼がどこまで進んでいるかが見える。開き方は導入した人が `.lassdas/progress.md` に書いている。

手元の docker で動かしている場合、盤面はその端末からしか見えない。**その端末が寝ていれば本体も止まっている**ので、依頼を出しても拾われるのは端末が起きた後になる。常時動かしたいなら置き場所を移す (導入した人へ)。

## 7. うまくいかないときの見分け

| 起きていること | たいてい原因はこれ |
|---|---|
| 立てたのに何も起きない | カテゴリが付いていない / 起票者が違う / 後からカテゴリを付けた |
| 答えたのに進まない | 別の人が答えた / 質問より前のコメントに書いた / 期限を過ぎていた |
| 状態を戻したのに動かない | 状態は表示なので、戻しても入力にならない |
| 夜に出した依頼が朝まで動かない | 手元の端末で動かしていて、端末が寝ていた |
